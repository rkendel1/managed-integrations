## Capability-layer gaps

- Capability **reads** are not audited. The existing `audit_log` covers state changes only. AppPort
  exposes telemetry hooks; no sink is wired yet.
- The MCP adapter is stateless (one `Server` per HTTP request). Revocation is therefore the session
  cookie's expiry/deletion, re-checked on every call; there is no MCP-specific session to revoke.
- The authorizer's tenant policy is code, not data. Per-user or per-tenant grants are not modelled.

## Known gaps (also in KNOWN-LIMITATIONS)

- The maintenance container mounts the **Docker socket** (root-equivalent on the host). Mitigation for
  production: run the maintenance service on a separate host/VM or use rootless Docker; it holds no
  customer credentials either way.
- No MFA for operators; no per-user password reset flow; seed creates the initial accounts.
- CSP header not set (UI is same-origin, no third-party scripts).
- Dependency installation during repair is offline-only from the image's store (no new packages possible),
  which is intentional; dependency vulnerability scanning is not automated.
- Customer data (order names, emails) appear in fixture data only; production PII handling (retention,
  Shopify protected-customer-data review) is not yet assessed. We do not store order emails.
